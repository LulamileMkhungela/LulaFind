# Android, end to end

Why the app on your phone must match the code in Git — and how this repo now
guarantees that. Read this if you have ever seen **"old UI in Android Studio"**
or **"… plugin is not implemented on android"** after pulling.

## What was wrong (and is now fixed)

The native Android shell (`lulafind/android/`) is committed to Git, but the
*packaged web app* is not: `android/app/src/main/assets/public/` (the built UI)
and `assets/capacitor.plugins.json` (the plugin registry) are generated by
`npx cap sync` and ignored. After pulling new web code and pressing **Run** in
Android Studio, Gradle happily packaged whatever a previous `cap sync` had left
behind on that machine. Three symptoms, one cause:

| Symptom | Cause |
| --- | --- |
| Old UI on the phone | stale `assets/public/` from a previous sync |
| `FirebaseAuthentication plugin is not implemented on android` (and Camera / Geolocation / …) | stale `capacitor.plugins.json` that does not list the plugin — the native half is in the APK but the bridge never registers it |
| A blank white screen on a machine that never synced | no `assets/public/` at all |

Two fixes, both in place:

1. **The Gradle build syncs itself.** `android/app/build.gradle` now has a
   `capSync` task wired into `preBuild`. It runs `npm run android:prepare`
   (`ng build --configuration production && cap sync android`) in `lulafind/`
   before every native build. Pressing **Run** in Android Studio or running
   `./gradlew assembleDebug` therefore always packages the current web app with
   every plugin registered. The task is skipped when nothing on the web side
   changed, and repeat runs stay fast.

   Opt out for a native-only experiment (not recommended — the APK then holds
   whatever assets exist):

   ```bash
   cd lulafind/android && ./gradlew assembleDebug -PcapSync.skip=true
   # or: CAP_SYNC_SKIP=1 ./gradlew assembleDebug
   ```

2. **The Capacitor glue Gradle files are committed.** `settings.gradle`
   includes `:capacitor-cordova-android-plugins` and `capacitor.build.gradle`
   applies its `cordova.variables.gradle`, so a fresh clone could not even
   *configure* before. Those static files (`build.gradle`,
   `cordova.variables.gradle`, the manifest) are now in Git; only their build
   output stays ignored.

## Google sign-in on Android — the full chain

`capacitor.config.ts` uses `FirebaseAuthentication: { skipNativeAuth: true }`:
the native plugin shows Google's own account sheet, then the Firebase JS SDK
holds the session from the returned ID token. For the sheet to open, all of
this must hold — everything except the console steps is already in the repo:

1. `npm install` once in `lulafind/` (Node 22+).
2. `google-services.json` in `lulafind/android/app/` — **committed** ✓
   (`com.lulafind.app`, web-client id included).
3. The plugin registered in the APK — **automatic since the `capSync` task**
   (`assets/capacitor.plugins.json` lists `FirebaseAuthenticationPlugin`).
4. **Firebase console:** the Android app must have this machine's SHA-1
   fingerprint, or Google answers the sign-in with `DEVELOPER_ERROR`
   (codes 10 / 12500). The app now maps that to a plain-language message.

   ```bash
   cd lulafind/android && ./gradlew signingReport   # read the SHA-1 of the debug variant
   # Firebase console → Project settings → Your apps → Android app → Add fingerprint
   # then download google-services.json into lulafind/android/app/ and rebuild
   ```

   The committed `google-services.json` already contains an OAuth web client,
   so if sign-in still refuses after adding the fingerprint, also check
   **Authentication → Sign-in method → Google: Enabled**.
5. iOS additionally needs `cap sync ios` on a Mac (Pods/SPM) — see README.

If the module is ever missing from a build anyway (an APK packaged with
`-PcapSync.skip=true`, say), the sign-in screen says exactly that instead of
the raw Capacitor error, and the same guard exists for Camera, Geolocation,
PushNotifications and Share — the UI reports "not part of this build" rather
than crashing on an unimplemented plugin.

## Permissions, end to end

Declared in `AndroidManifest.xml`, asked at the moment a feature needs them,
and auditable in **Me → Settings → Phone permissions**:

| Permission | Declared | Asked when | Requested by |
| --- | --- | --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE` | install-time | — (no prompt) | OS |
| `ACCESS_FINE_LOCATION` / `COARSE` | install-time | attaching a map pin to a sighting; safety check-ins; "cases near you" | `Geolocation.requestPermissions()` via `LocationService` / `PermissionsService` |
| `CAMERA` | install-time | taking a photo for a post, story or profile | `Camera.requestPermissions()` via `MediaService` (gallery fallback on refusal) |
| `READ_MEDIA_IMAGES` / `VIDEO` + `READ_MEDIA_VISUAL_USER_SELECTED` | install-time | picking photos/videos (Android 13/14; "Select photos" partial access included) | Capacitor Camera / the system photo picker |
| `READ/WRITE_EXTERNAL_STORAGE` | `maxSdkVersion` scoped (32 / 28) | only on old Android versions | OS |
| `POST_NOTIFICATIONS` | install-time (runtime on 13+) | turning alerts on in Settings | `PushNotifications.requestPermissions()` via `PermissionsService` |
| `VIBRATE` | install-time | — (haptics) | OS |

Push goes one step further than the OS toggle: granting notifications now
calls `PushNotifications.register()` (`PushService`), stores the FCM token in
Preferences (`lulafind.push.token`), and surfaces registration errors in
Settings instead of swallowing them. Already-permitted devices register
silently at app start. Sending from a backend to those tokens is the one part
that lives outside this repository.

## Daily workflow

```bash
cd lulafind
npm install          # once per clone
npm run android:prepare   # web build + cap sync (also run by every Gradle build)
npm run cap:android  # open Android Studio, press Run
```

After changing only web code you can simply press **Run** again — Gradle
re-syncs. After changing native files or plugin versions, also let Android
Studio re-sync Gradle as usual.
